# EFS Asset Garbage Collector (`asset-processor`)

A high-performance CLI utility designed to process and identify orphan assets stored in AWS EFS (or local filesystem storage) and perform cleanup actions.

The application ingests log files generated by DevOps (from AWS S3 or a local path) containing file paths associated with entity scopes (`COMPANIES` or `PERSONS`). It verifies asset existence against active database records (PostgreSQL) and executes configured actions on orphan assets.

---

## 📸 Overview & Architecture

```text
+-----------------------+
|   DevOps Log Files    |
| (AWS S3 / Local Path) |
+-----------+-----------+
            |
            v
+-------------------+   +-------------------------+   +-------------------+
|   PostgreSQL DB   |<--| Asset Garbage Collector |-->|  Target Storage   |
| (jOOQ / Active)   |   |  (Java / Picocli CLI)   |   | (EFS / Quarantine)|
+-------------------+   +-------------------------+   +-------------------+
```

### Key Capabilities
* **Idempotency & Checkpoints:** Tracks progress line-by-line via local checkpoints, allowing seamless resume on unexpected interruptions. Tagged log files are marked as processed to avoid redundant runs.
* **Concurrency Control:** Supports both single-file sequential processing and multi-file parallel processing using dedicated thread pools (`EfsFileWorker`).
* **Safety First:**
  * **Dry-Run Mode:** Runs full scans without altering files or writing state tags.
  * **Critical Infrastructure Safety:** Automatically aborts execution if DB or network connection failures occur to prevent false-positive orphan detection.

| `DB_PASSWORD` | Database password | `****` |

| `AWS_PROFILE_NAME` | AWS Named Profile for local development | `pisca-dev` |

| `S3_BUCKET_NAME` | AWS S3 Bucket containing log files (if `GC_SOURCE_TYPE=S3`) | `eu-west-1-dev-piscapt-media-log` |

## 🚀 CLI Arguments & Options

The application uses **Picocli** for argument parsing and validation.

```bash
java -jar asset-processor.jar [OPTIONS]
```

### Parameters Reference

| Option | Required | Type / Allowed Values | Default | Description |
| :--- | :---: | :--- | :--- | :--- |
| `--scope` | **Yes** | `COMPANIES`, `PERSONS` | *None* | Scope of entities to process. |
| `--mode` | **Yes** | `SEQUENTIAL`, `PARALLEL_FILES` | *None* | Execution mode for file processing. |
| `--orphan-action` | **Yes** | `MOVE_TO_QUARANTINE`, `DELETE`, `WRITE_TO_REMOVE_FILE` | *None* | Action to take when an orphan asset is identified. |
| `--dry-run` | No | `true`, `false` | `true` | When true, simulates execution without deleting/moving files or saving progress tags. |
| `--skip-processed`| No | `true`, `false` | `false` | When true, ignores log files that were previously marked as processed. |
| `--ids` | No | Comma-separated SecretId string | *Empty* | Filter execution to specific entity HashIDs (e.g., `--ids=ABC12,XYZ89`). |
| `--parallel-files`| Conditional| Integer (> 0) | *Config default* | Number of log files to process concurrently. Only valid with `--mode=PARALLEL_FILES`. |

### Orphan Actions Explained
* **`MOVE_TO_QUARANTINE`:** Moves identified orphan asset files from their original location into the configured `QUARANTINE_FOLDER`.
* **`DELETE`:** Permanently removes orphan asset files from the filesystem/EFS.
* **`WRITE_TO_REMOVE_FILE`:** Scans orphans and logs their paths into a designated manifest file for manual review or scheduled cleanup without immediate deletion.

## 🛠️ Usage Examples

### 1. Dry Run (Safe Test) in Sequential Mode
Runs a simulation over company logs, outputting potential deletions without altering any files:

```bash
java -jar asset-processor.jar \
  --scope=COMPANIES \
  --mode=SEQUENTIAL \
  --orphan-action=WRITE_TO_REMOVE_FILE \
  --dry-run=true
```

### 2. Live Quarantine Run (Parallel Mode, Skipping Processed)
Processes person logs concurrently across 4 log files in parallel, moving orphans to quarantine and skipping previously completed files:

```bash
java -jar asset-processor.jar \
  --scope=PERSONS \
  --mode=PARALLEL_FILES \
  --parallel-files=4 \
  --orphan-action=MOVE_TO_QUARANTINE \
  --dry-run=false \
  --skip-processed=true
```

### 3. Target Specific Entity IDs
Runs execution restricted to specific encrypted/hashed entity IDs:

```bash
java -jar asset-processor.jar \
  --scope=COMPANIES \
  --mode=SEQUENTIAL \
  --orphan-action=DELETE \
  --ids=aB3xZ,k9LmP \
  --dry-run=false
```

## 🏗️ Building and Execution

### Build Package
Ensure Java 21+ and Maven/Gradle are configured:

```bash
# Using Maven
mvn clean package

# Output JAR location: target/asset-processor.jar
```

### Run Executable
Ensure the `.env` file is present in the working directory before running:

```bash
java -jar target/asset-processor.jar \
  --scope=COMPANIES \
  --mode=SEQUENTIAL \
  --orphan-action=WRITE_TO_REMOVE_FILE
```
